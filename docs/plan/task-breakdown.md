# 任务分解

## 概览

- **目标**：交付 Apple Silicon 原生 `Grok Build Switch.app`、DMG 和 ad-hoc 签名，同时保留 Windows 能力。
- **阶段数**：3
- **任务数**：9
- **总工作量**：L
- **执行策略**：自底向上，先隔离平台端口，再构建交付物，最后进行真实验证与 fork 同步。
- **执行方式**：当前规则未授权子代理，所有任务按依赖顺序执行；Lane 仅记录理论并行关系。

## S.U.P.E.R 设计约束

- **S 单一职责**：LaunchAgent、Grok CLI 定位、菜单栏资源与应用打包分别实现，不合并成通用“macOS 工具”文件。
- **U 单向依赖**：`main/server/tray` 只依赖平台端口，不反向暴露业务层给系统命令实现。
- **P 端口优先**：plist 生成、命令候选和打包参数必须有明确输入输出，尽量设计为纯函数。
- **E 环境无关**：不得写死用户名或当前工作区；Homebrew 路径只能作为候选，不得替代 PATH 和环境变量。
- **R 可替换组件**：Windows 注册表、macOS LaunchAgent 和其他平台降级实现使用构建标签隔离。

## 测试与治理约束

- 所有行为改动必须新增或更新自动化测试。
- 构建与文档任务至少运行 shell 语法、plist、应用目录、二进制架构和 Markdown 链接验证。
- 保持 `GROK_HOME`、`GROK_CONFIG`、`~/.grok_switch`、现有 JSON API 和 Windows 构建兼容。
- 本次没有可写的原生项目记忆，也未获准创建仓库内记忆文件；稳定结论记录在计划、进度和最终归档中。
- 如产生未来代理必须遵守的新规则，再评估是否需要用户确认后创建 `AGENTS.md`。

## 通用验收清单

每个任务完成前执行以下 10 项快速审查，并把分数写入进度遥测：

1. 新模块只有一个职责。
2. 没有重复的平台逻辑。
3. 依赖方向仍由 UI/系统适配层指向核心。
4. 没有新增循环依赖。
5. 跨模块输入输出有明确类型或文件格式。
6. 可纯测逻辑与真实系统命令分离。
7. 没有用户名、仓库绝对路径或敏感值硬编码。
8. 构建输入和外部工具有明确检查与错误信息。
9. Windows 原有行为和构建文件保持可用。
10. macOS 适配可通过构建标签或脚本独立替换。
